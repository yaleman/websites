# System Design Updates

- 2026-03-07: Replaced raw SQL schema bootstrapping with SeaORM migrations (`sea-orm-migration`) and set SQLite foreign keys via the connection URL.
- 2026-03-08: Documented the rendering split: admin UI templates use Askama from `templates/`, while site previews and published site output use Tera from `site_templates/`.
- 2026-03-08: Site previews now rewrite `/assets/...` references to an authenticated preview asset route that serves files from `site_templates/<template>/assets/`.
- 2026-03-08: Added a global user admin flag that bypasses per-site membership checks for admin routes; site memberships remain limited to viewer/author/editor/owner roles. Published site rendering now copies uploaded media from the resolved runtime upload root instead of assuming a fixed relative path.
- 2026-03-08: Added a user profile admin view keyed by database user UUID. Global admins can view any user profile, and non-admin users can view only their own profile; the view shows stored user details plus site memberships.
- 2026-03-09: Added per-site template overrides stored under the runtime upload root at `.site-template-overrides/<site_id>/`. Site preview and render load these overrides before the shared `site_templates/<template>/` files, and the admin UI currently edits template files only, not template asset directories.
- 2026-03-09: Site memberships can only be granted to users who already exist from a prior login. The admin memberships page now presents an autocomplete picker over known user email/subject values instead of free-form subject entry.
- 2026-03-09: User records now persist the OIDC display-name claim when available, and the admin user profile shows that display name alongside subject and email.
- 2026-03-14: Added a `settings` key/value table backed by JSON values and enum keys. The admin server now creates and persists an HS256 API JWT signing secret there on first startup instead of reading it from CLI or environment.
- 2026-03-14: Added DB-backed user API tokens with revocation, last-used tracking, and idle expiry 7 days after last successful use. Token grants are either unrestricted current-user access (`grants_json` unset) or a restricted subset of current site/admin permissions.
- 2026-03-14: `/api/...` routes now accept OAuth2-style bearer tokens in addition to existing session auth. Admin HTML routes remain session-authenticated, and the admin UI now includes manual user creation plus per-user token issuance and revocation screens.
- 2026-03-17: Added site-scoped content and asset API endpoints for content list/search/create/get/update/delete and asset list/get/upload/delete, while retaining the asset-library search endpoint for the editor. These `/api/...` routes return JSON error bodies, reuse the existing site-role and bearer-token auth model, and are covered by generated OpenAPI, Rust handler tests, and a repo-managed Python generated-client test package.
- 2026-03-17: The admin runtime database path now resolves from `WEBSITES_DB_PATH` when set, otherwise it falls back to the existing `./database.sqlite` default. Container builds set `WEBSITES_DB_PATH=/data/websites.sqlite` by default.
- 2026-03-15: Added an unauthenticated `GET /health` endpoint on the admin server that returns JSON `"ok"` for simple liveness checks without touching auth or the database.
- 2026-03-09: Unmatched routes now render a human-facing 404 page with the requested path and a link back to `/` instead of returning Axum's default plain response body.
- 2026-03-25: Reworked the admin frontend styling pipeline to use Tailwind CSS through the existing Rspack build. The admin shell, editor, asset picker, and remediation flows now render with Tailwind utility classes and Tailwind-backed component layers, while the public site templates remain on their existing theme system.
- 2026-03-26: The site template root is now configurable from the top-level CLI and `WEBSITES_SITE_TEMPLATES_DIR`. The admin server and CLI site render path both use the parsed root, while the default remains `./site_templates/` and Docker now sets the container default to `/site_templates`.
- 2026-03-26: The rendered output root is now configurable from the top-level CLI and `WEBSITES_RENDERED_DIR`. The admin server and CLI site render path both use the parsed root, while the default remains `./rendered/` and Docker now sets the container default to `/data/rendered`.
- 2026-03-26: The upload media root is now configurable from the top-level CLI and `WEBSITES_UPLOAD_ROOT`. The admin server and CLI asset paths both use the parsed root, while the existing filesystem fallback remains in place and Docker now sets the container default to `/data/uploads`.
- 2026-03-09: `content_revision_alias` and `content_revision_tag` now store a direct `content_id` foreign key to `content_item` alongside `revision_id`, so revision child rows remain tied to the owning content item without relying on an indirect join.
- 2026-03-09: Site transfer uses one versioned JSON document for export and import. CLI and admin UI can import/export site-scoped database records, but v1 only records filesystem metadata for uploaded media and template overrides, not file bytes.
- 2026-03-09: Site exports are available through the CLI and an owner-only admin download endpoint as a versioned JSON document containing site-scoped database records plus uploaded media/template-override file metadata, but not file bytes.
- 2026-03-09: Site settings now expose a delete-site action only to global admins; deletion removes the site row plus site-owned uploaded media files and template override files.
- 2026-03-09: Admin destructive POST flows can use session-backed CSRF tokens issued and validated through a reusable `Session` extension; site deletion confirmation uses this token check.
- 2026-03-10: Added a site-scoped content remediation UI at `/admin/site/<site_id>/content/scan` that scans current content bodies for link, image, and simple HTML cleanup issues and applies selected fixes by creating new revisions.
- 2026-03-10: Content bodies can now reference site assets with `[[asset id="<uuid>" variant="<original|thumbnail>" alt="<text>" title="<optional caption>"]]`; preview and publish expand this shortcode before Markdown rendering into `<figure><img></figure>` with optional `<figcaption>`.
- 2026-03-10: Content remediation now scans site content in ascending effective update order (`last_updated` or `created_at`) and returns only the first user-selected number of pages that still have issues, rather than listing every scanned page at once.
- 2026-03-25: Added a global admin theme registry backed by SQLite. Shared themes are cloned into `site_templates/<slug>` with `gix`, auto-adopted when pre-existing git-backed directories are discovered, and managed through `/admin/themes` for install, update, and delete. Site creation and site settings now read from the registry instead of scanning the filesystem directly, while the built-in `default` theme remains special-cased.
- 2026-03-26: Added a site-scoped WordPress WXR import flow at `/admin/site/<site_id>/settings/wordpress-import`. The site content dashboard links to the import section on site settings, and repeat uploads skip already-imported content by reusing the existing alias/slug/page-type dedupe path.
- 2026-04-03: WordPress WXR imports now treat any supported item with a non-empty `wp:post_password` as password-protected, store it as a draft, prefix its stored title with `[PASSWORD-PROTECTED] `, and reconcile older matching imports in place instead of creating duplicates. The admin import toast and CLI output now also report updated existing titles alongside newly imported counts.
- 2026-03-26: The new content screen now auto-fills the slug from the title until the slug is explicitly hand-edited. The slug field stays read-only until the user confirms they want manual control, includes a reset action back to title-driven generation, and is placed last in the form tab order.
- 2026-03-26: Creating new content now redirects directly to the content edit screen and shows a success toast so the user can continue editing immediately after the initial save.
- 2026-03-27: Added a site publish workflow with a dedicated publish settings page linked from site settings. Publish configuration is stored per site, publish runs are tracked in the database, and the initial backend mirrors rendered output to an S3-compatible destination from a monitored background job.
- 2026-03-27: Application logs are now written to the persistent file configured by `WEBSITES_LOG_PATH` in addition to stdout, and the admin dashboard exposes a global-admin-only log viewer that tails and filters the current log file.
- 2026-03-27: Publish runs now link to a dedicated site-scoped detail page that shows the run record and the matching log events for that run ID. Clearing a publish config is done by setting the method to Disabled on the publish settings page.
- 2026-03-28: Added rsync-over-SSH publishing alongside S3 publishing. The publish settings page now shows only the method-specific config panel for the selected method, preserves hidden values until save, and the publish workflow dispatches to either S3 or rsync from the stored publish method.
- 2026-03-28: Added a `publish on render` site setting. When enabled, the render action publishes the rendered tree immediately after render completes, and the site navbar only shows the manual publish button when that setting is off.
- 2026-03-31: Site preview and render now fall back to bundled templates from `./site_templates/<template>/` and then `./site_templates/default/` even when `WEBSITES_SITE_TEMPLATES_DIR` points at a mounted runtime directory such as `/data/site_templates`. Docker images keep the configurable template root at `/data/site_templates` and also bundle the built-in templates at `/site_templates` so the built-in fallback remains available when `/data` is mounted.
- 2026-04-14: Admin asset upload and replace now raise the multipart body limit to 50 MB so multi-file image uploads do not hit Axum's default 2 MB cap. Multipart failures on those routes now return explicit 4xx responses instead of opaque 500s, and server-side 5xx responses log their error details.
- 2026-03-31: The template fallback contract is now explicit: preview and render must keep working when `WEBSITES_SITE_TEMPLATES_DIR` points at an empty or partial mounted runtime directory, and bundled fallback lookup must not depend on the process working directory. The loader now probes the bundled `site_templates/` tree from the configured relative path, the packaged binary location, and the source-tree location used by tests.
- 2026-04-05: The admin content editor now supports Markdown pipe tables in rich-text mode through TipTap table controls. Stored table syntax round-trips through the Markdown source view, and site preview/publish render those tables with GFM table parsing enabled on the Rust markdown path.
- 2026-04-03: Admin asset browsing now supports explicit sort controls for upload date, file size, and original filename on the site assets page, the upload page asset browser, and both asset picker modals. The shared `/api/site/<site_id>/assets/library` query contract accepts `sort_by` and `sort_dir`, and picker responses now include `byte_length` so the UI can display the active sort context.
